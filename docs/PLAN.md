## A. 選択時の描き直しを速くする

**ねらい**　枠を選ぶたびに全段を VexFlow で組み直していて、Tea for Two では1回約90ミリ秒かかる（`tools/smoke.py` の最後の行に出る）。矢印キーでの移動が重い。

**仕様**
- `vfSystem(b0,bars,first,last,bps,units)` の結果（`{clefW, W, M, svg, barW}`）を段ごとにキャッシュする。
- キャッシュのキーは、その段の見た目を決めるものすべて：
  `state.songId`、`xp.name`、`bps`、`b0`、`HB`、`T`、`DEG_Y`、その段の各枠の `[s, l, root, q, bass]`、
  そして伴奏付けモードで未設定の枠があるときの骨格の音（`skelIdx` の結果。旋律だけで決まるので、枠の `s, l` があれば足りる）。
- **選択中の枠（`state.sel`）、逆算の着地点や鎖、再生位置はキーに入れない。** これらは `svg()` が文字列を作るときに毎回読むので、キャッシュした結果のまま正しく出る。`svg()` の中で `state.sel` を参照している所はそのままでよい。
- キャッシュは `Map` で持ち、上限 64 段。`loadSong`、`setKey`、Undo/Redo では消さなくてよい（キーが変わるので自然に外れる）が、上限を超えたら古い順に捨てる。
- `vfSystem` の中で使っている共有の `vfHost`（隠し要素）は、結果を文字列（`inner`）に写したあとは参照していないことを確かめる。

**受け入れ条件**
1. `python3 tools/smoke.py` の「selection change on Tea for Two」が 20 ms 以下。
2. コードを置き換えた段だけ音符の色が変わり、ほかの段は変わらない。置き換え・分割・結合・Undo・移調・幅の変更（2小節／4小節の切り替え）・ベース行の表示切り替えのあと、表示がキャッシュなしのときと同じ。
   - 確かめ方：キャッシュを無効にする一時的なフラグを用意し、上の操作のあとで `#sheet` の `innerHTML` が一致することを `tools/smoke.py` に1か所足して確かめる（フラグは残してよい。名前は `VF_CACHE`）。
3. `node --test` が通る。

**実装メモ**
- `vfSystem` を2つに分けた：重い組版を `vfEngrave`（VexFlow の SVG を文字列 `inner` にし、`x`・`edge`・`info` と返す）に移し、`vfSystem` はキーで `vfCache`（`Map`、上限 64、使うたびに末尾へ移して古い順に捨てる）を引いてから、`svg()` をその場で作る。`svg()` は今の `units`（枠の番号）と `state.sel` を読むので、前の段で分割して番号がずれてもキャッシュが使える。
- キーは計画の項目に加えて、音符の色（`--ct` などの CSS 変数の値。ライト／ダークで変わり、音符の塗りに焼き込まれるため）。骨格の音は枠の `s, l` で決まるのでキーに別途入れていない。自作曲を編集して保存すると同じ id のまま中身が変わるので、`saveEditor` の処理（`#edForm` の submit）で `vfCache.clear()` する。
- `vfHost` は `inner` を写したあとは読んでいない（`x`・`edge` は `info` の数値だけを使う）。
- `tools/smoke.py` に、Tea for Two で置き換え・分割・結合・Undo・移調、きらきら星でベース行の表示／非表示、幅 480px（2小節）と 1280px（4小節）のあと、`VF_CACHE=false` と `#sheet` が一致するかを足した。VexFlow が付ける `vf-auto123` の id は毎回変わるので除いて比べる。最後の枠を置き換えたとき最後の段の `.vfw` だけが変わることも見ている。キーから `root` などを抜くとこの検査が落ちることも確かめた。
- 選択の変更（Tea for Two）：この環境ではキャッシュなし 約25 ms → あり 約7 ms（計画の「約90ms」より速い環境だった）。
- `tools/smoke.py` は、この環境に Playwright がなかったので作業用の venv に入れて実行した（Chromium はサンドボックス外で起動）。

## C. 用語の説明を広げる

**ねらい**　いまは凡例の5語（和声音・テンション・アボイド・非和声音・骨格の音）だけ、押すと説明が出る。ガイドの文に出てくる用語も、その場で説明を開けるようにする。

**仕様**
- `js/app.js` の `TERM_TEXT` を用語集として広げる。足す語と説明（文面はこのまま使う）：

| id | 用語 | 説明 |
|---|---|---|
| `fn` | 機能（T・S・D） | コードの働きのことです。T（トニック）は落ち着く所、S（サブドミナント）は少し動きたくなる所、D（ドミナント）は T に戻りたくなる緊張です。T → S → D → T が基本の流れです。 |
| `deg` | 度数 | 調の主音から数えたコードの位置を、ローマ数字で書いたものです。ハ長調なら C が I、F が IV、G7 が V7 です。度数で覚えると、どの調でも同じ考え方が使えます。 |
| `sec` | セカンダリードミナント | I 以外のコードを一時的な着地点とみなして、その5度上に置く 7th コードです。ハ長調で Dm の前に置く A7 がその例で、Dm へ強く引き寄せます。 |
| `twofive` | II–V | 着地点の手前に II と V を並べる形です（C へ向かう Dm7 → G7）。ジャズでいちばんよく使う進行で、V7 ひとつを II–V に分けることもできます。 |
| `sub` | 裏コード | V7 の代わりに使える、増4度離れた 7th コードです（G7 の代わりに D♭7）。大事な2音（3度と7度）が共通で、ベースが半音で下りて着地します。 |
| `bor` | 借用 | 同じ主音の短調（短調の曲なら長調）のコードを、一時的に借りてくることです。ハ長調で Fm や B♭7 を使うと、少し陰った響きになります。 |
| `slash` | 分数コード | C/E のように書き、「C のコードで、ベースは E」という意味です。ベースだけを変えて、低音の線をなめらかにします。 |
| `decept` | 偽終止 | V から I へ進まず、VIm などへ進む形です。終わると思わせて続けるので、フレーズを先へつなげられます。 |
| `cliche` | クリシェ | 同じコードが続く所で、コードの中の1音だけを半音ずつ動かす手法です（C → Cmaj7 → C7）。止まっていた響きに線が生まれます。 |

- 文の中の用語を、押せる形に自動で変える関数 `glossed(html)` を作る。
  - 対象の語（左が文中の表記、右が id）：`T・S・D`→`fn`、`セカンダリードミナント`→`sec`、`II–V`→`twofive`、`裏コード`→`sub`、`借用`／`借りて`→`bor`、`分数コード`→`slash`、`偽終止`→`decept`、`クリシェ`→`cliche`、`テンション`→`tn`、`骨格の音`→`sk`、`アボイド`→`av`。
  - 1つの文（1回の `glossed` 呼び出し）の中で、同じ id は**最初の1回だけ**ボタンにする。
  - HTML タグの中身（属性やタグ名）は置き換えない。すでにボタンになっている所も置き換えない。
- `glossed` を通すのは：リハモのガイドの説明（`RDESC`）、候補グループの説明（`TECH[*].desc`、`harmSuggest` の `desc`）、伴奏付けのガイドの各ステップ冒頭の説明文。**候補ボタンの中や楽譜の中には使わない。**
- 選択中の枠のバーの「機能」「度数」の見出し語も、それぞれ `fn`、`deg` のボタンにする。
- 押したときの動き：
  - ボタンのある段落のすぐ下に、説明の箱（凡例の `.termbox` と同じ見た目）を出す。もう一度押すと閉じる。別の語を押すと、前の箱は閉じる。
  - 右のパネルは描き直しで中身が作り直されるので、開いている用語の id を変数で覚えておき、描き直しのあとも開いたままにする。枠の選択が変わったら閉じる。
  - クリックは `document` への1つの委譲で受ける（凡例のボタンも同じ処理に統合する）。
- 見た目：文中のボタンは下に点線（凡例の `.term` と同じ）。色の丸は付けない。

**受け入れ条件**
1. リハモのガイドのステップ「次のコードへ向かう」で、「セカンダリードミナント」「II–V」を押すと、その段落の下に説明が出る。もう一度押すと閉じる。
2. 説明を開いたまま候補を選んでも（描き直しが起きても）、エラーが出ない。
3. 凡例の5語は今までどおり動く。
4. 用語のボタンにフォーカスがあるとき、スペースキーは再生でなくボタンの操作になる（`spaceFree` がそうなっていることを確かめる）。

**実装メモ**
- `js/app.js`：`TERM_TEXT` に9語を計画の文面のまま足した。`GLOSS`（文中の表記 → id）、`termBtn(id, 表記)`、`glossed(html)` を追加。`glossed` は HTML をタグと文字に分け、文字の部分だけを置き換える。`<button>`〜`</button>` の中は置き換えない。同じ id は1回の呼び出しで最初の1回だけ。
- クリックは `document` への1つの委譲（凡例の `.term` も同じ処理）。凡例の語は今までどおり `#termbox` に、パネルの語は `closest("p, .selrow")` のすぐ後ろに `.termbox.glossbox` を出す。開くのは全体で1つだけ。
- 描き直しのあとも開いたままにするため、`renderInsp` を `renderInspBody` ＋ `restoreTerm()` に分けた。`openTerm` には id、同じ id のボタンの何番目か、選択中の枠を覚えている。枠の選択が変わっていたら閉じる。
- `glossed` を通したのは、`RDESC`、候補グループの説明（`candHtml` の `g.desc`。`TECH[*].desc` と `harmSuggest` の `desc` の両方がここを通る）、伴奏付けのガイドのステップ1〜6の最初の段落。選択中の枠のバーの「機能」「度数」は `termBtn("fn")`／`termBtn("deg")`。
- 確かめたこと（Playwright で幅 1280／480px）：「次のコードへ向かう」で「セカンダリードミナント」を押すと段落の下に箱が出て、もう一度押すと閉じる。「II–V」も同じ。開いたまま候補を押しても（描き直し）エラーは出ず、箱は開いたまま。枠を替えると閉じる。凡例の5語も開閉できる。バーの「機能」にフォーカスしてスペースを押すと、再生されずに説明が開く（`spaceFree` は `.slot` 以外のボタンでは false なので、変更は不要だった）。スクリーンショットは両方の幅で目で確かめた。
- 気づいた点：ガイドの「原曲を読む」の説明は「T（安定）・S（広がり）・D（緊張）」と書いてあり、対象の表記「T・S・D」と一致しないのでボタンにならない。伴奏付けのステップ4も「T（トニック）→ S …」なので同じ。

## D. 「はじめに」の案内

**ねらい**　初めて開いた人が、何をすればよいかわからない。

**仕様**
- ヘッダーのモード切り替えの左に、`使い方` ボタン（`.btn`、id `helpBtn`）を置く。
- ツールバーの下、楽譜の上に、案内の箱（id `intro`）を出す。中身はモードで変える：

  リハモ
  1. 曲を選んで「全体を再生」で聴きます。
  2. 楽譜の上のコード名（枠）を押して選びます。
  3. 右の「ガイド」の提案を選ぶと、コードが置き換わって音が鳴ります。音符の色と下の数字で、メロディとの相性がわかります。
  4. 気に入らなければ「元に戻す」（Ctrl+Z）。ステップを進めると、手法が少しずつ増えます。

  伴奏付け
  1. 曲を選んで「全体を再生」で旋律を聴きます。
  2. 右の「ガイド」のステップ1から、順にコードを決めていきます。
  3. コードを置くと音符に色が付き、合っているかどうかがわかります。
  4. 全部置けたら「原曲のコードを見る」で見比べます。

- 箱の右上に `閉じる` ボタン。閉じたら `rehamo:intro` を保存し、次回からは出さない。`使い方` を押すと、出ていなければ出し、出ていれば閉じる（保存も合わせて更新）。
- 保存が使えない環境（`localStorage` が例外を出す）でも動くこと。そのときは毎回出てよい。
- モードを切り替えたら、中身も切り替わる（`applyHarmUi`）。

**受け入れ条件**
1. 保存が空の状態で開くと箱が出る。閉じて読み込み直すと出ない。`使い方` で出し入れできる。
2. 幅 480px で、箱がはみ出さず、ツールバーと重ならない。
3. 箱が出ていても、楽譜の段の折り返し（4小節／2小節）に影響しない。

**実装メモ**
- `index.html`：ヘッダーのモード切り替えと `使い方`（`#helpBtn`）を `.topbtns` でまとめ、ボタンを左に置いた。ツールバーの後ろ（`header` の中、`.main` の前）に `#intro`（見出し「はじめに」、`閉じる`、`#introSteps`）を置いた。見出しの「はじめに」は計画に文面がないので、項目名から取った。
- `js/app.js`：文面は `INTRO_REHARM`／`INTRO_HARM`（計画のまま）。`applyHarmUi` で `#introSteps` を差し替える。`showIntro(on)` が表示と `rehamo:intro`（閉じていれば true）を合わせて更新する。起動時は `store.get("rehamo:intro")` が true でなければ出す。`store` は例外を握りつぶすので、保存が使えない環境では毎回出る。
- 確かめたこと（Playwright）：保存が空なら出る。閉じて読み込み直すと出ない。`使い方` で出し入れできる。モードを替えると文面も替わる。`localStorage` が例外を出す環境でもエラーなしで出る。幅 1280／480px で、箱はツールバーの下にあって重ならず、はみ出さない。`barsPerSystem()` は箱の有無で変わらない（4／2）。スクリーンショットは両方の幅で目で確かめた。

## E. 伴奏付けの答え合わせ

**ねらい**　「原曲のコードを見る」は一致した枠数だけで、違う枠について何も言わない。原曲と違っても成り立つ答えは多いので、そこを伝える。

**仕様**
- 関数 `answerNote(i)` を `js/guide.js` に作る。伴奏付けモードで「原曲のコードを見る」がオン、かつ枠 `i` にコードがあるときに、1行の文を返す。それ以外は空文字。
  - `c`＝いまのコード、`o`＝`origAt(i)`、`K`＝`keyOfCell(i)`、`A`＝`analyze(c,K)`、`O`＝`analyze(o,K)`、`v`＝`verdict(rolesFor(c,i))`。
  - 枠の区切りが原曲と違う（`!sameCell(state.chords[i], o)`）ときは、文の頭に「原曲とはコードを変える位置が違います。」を付ける。
  - 場合分け（上から順に当てはまったもの）：
    1. `same(c,o)` → 「原曲と同じコードです。」
    2. `v==="bad"` → 「骨格の音がぶつかっています。原曲は ○○ です。」
    3. 根音が同じで種類だけ違う → 「原曲（○○）と根音が同じで、響きの厚さが違うだけです。」
    4. `A.fn && A.fn===O.fn` → 「原曲（○○）と同じ機能（T／S／D）です。別の答えとして成り立ちます。」
    5. `A.fn && O.fn` → 「原曲（○○）とは機能が違います（あなた：S、原曲：D）。メロディには合っているので、流れを聴き比べてみましょう。」
    6. それ以外 → 「原曲は ○○ です。メロディには合っています。聴き比べてみましょう。」
  - ○○ は `sym(o)`。
- 出す場所：選択中の枠のバーの判定の行（`verdictMsg` の文の後ろ）。
- 楽譜の上の集計（`#summary`）の「原曲と同じ：n 枠」の後ろに、「同じ機能：k 枠」を足す（同じコードの枠は k に含めない）。「（違っていても、合っていれば正解です）」の注記は残す。

**受け入れ条件**
1. きらきら星の伴奏付けで、原曲 C の枠に Am を置き「原曲のコードを見る」をオンにすると、4 の文が出る。G7 の枠に F を置くと 5 か 2 の文が出る。
2. リハモモード、および「原曲のコードを見る」がオフのときは、何も出ない。
3. 転調区間（Tea for Two の9〜15小節）でも、その調での機能で比べる。

**実装メモ**
- `answerNote(i)` を `js/guide.js` に追加（場合分けと文面は計画のまま）。「根音が同じ」は `rootPc` の一致で見ている。`selbarHtml` の `.vmsg` の文の後ろに、空でなければ半角スペースを挟んで付ける。
- `render`（`js/score.js`）で、伴奏付け・「原曲のコードを見る」オンのとき、同じコードでない枠のうち `analyze(c,K).fn` が原曲と一致するものを `fnMatch` と数え、「原曲と同じ：n 枠、同じ機能：k 枠（違っていても…）」と出す。`K` は `keyAt(c.s)`。
- 確かめたこと（Playwright）：きらきら星で1小節目に Am → 4 の文（「原曲（C）と同じ機能（T）です…」）。4小節目に F → 5 の文（あなた：S、原曲：D）。1小節目を Cmaj7 → 3 の文。オフのときとリハモでは空。Tea for Two の10小節目（原曲 Dm7）は、転調区間の調で S と判定される（曲の調では機能なし）。Fmaj7／F6 → 4、Dm → 3、Am7 → 5、Fm7 → 2。枠が1小節で原曲が半小節のときは、頭に「原曲とはコードを変える位置が違います。」が付く。スクリーンショット（1280／480px）を目で確かめた。
- 気づいた点：幅 720px 以下では `.selbar .vmsg` が既存の CSS で隠れるので、この文はスマートフォンでは出ない（「未決」に書いた）。

## F. 再生のくり返しと音量バランス

**仕様**
- 「再生」の行に、チェックボックス `くり返す`（id `loopOn`）を足す。オンのとき、`playRange` は終わりまで来たら同じ引数で最初から再生し直す（全体、ここから、前小節から、聴き比べ、原曲のどれも）。停止は今までどおり。
  - くり返しの継ぎ目で音が途切れすぎないよう、次の周回は終わりの拍にそろえて始める（`tick` で `beat>=b1` を見た時点で `playRange(...)` を呼び直す形でよい。`startBeat` は元の開始位置）。
  - 再生中にテンポを変えたときの再開（`bpmTimer` の処理）でも、くり返しの設定と元の開始位置が保たれること。`play` に元の開始位置を持たせる。
- 同じ行に、スライダー `メロディ ←→ コード`（id `mix`、0〜100、初期値 50）を足す。
  - 50 でいまと同じ音量。0 でコード（ベースを含む）が無音、100 でメロディが無音。間は直線でなく、聞いた感じが自然になるよう二乗で絞る：
    `melGain = min(1, (100-mix)/50)²`、`chordGain = min(1, mix/50)²`。
  - `tone` の `peak` に掛ける。再生中に動かしたら、テンポ変更と同じ仕組み（少し待ってから今の位置で鳴らし直す）で反映する。
- どちらも保存する（`rehamo:loop`、`rehamo:mix`）。
- 「メロディも鳴らす」のチェックは残す（オフなら mix にかかわらずメロディは鳴らない）。

**受け入れ条件**
1. くり返しオンで「ここから」を押すと、終わりまで行って、選んだ枠からまた鳴る。停止で止まる。
2. くり返しオンのまま聴き比べ（▶原曲）を押すと、4小節をくり返す。
3. mix を 0／100 にすると、片方だけが鳴る。50 は変更前と同じ音量。
4. 幅 480px で「再生」の行が折り返しても崩れない。

**実装メモ**
- `js/audio.js`：`playRange` に第6引数 `origin`（最初に再生したときの開始拍）を足し、`play.start` に持たせた。`tick` で `beat>=b1` かつ `state.loop` なら `playRange(from,to,chords,mode,start,start)` を呼び直す。`melGain()`／`chordGain()`（計画の式のまま）を `tone` の `peak` に掛ける（ベースはコード側）。
- `js/app.js`：テンポ変更の再開を `replayLater()` にまとめ、`p.start` を渡すようにした。mix のスライダーも同じ `replayLater()` で反映。`rehamo:loop`／`rehamo:mix` に保存し、`state.loop`／`state.mix`（`js/state.js`）として起動時に読む。
- `index.html`：「再生」の行に `くり返す`（`#loopOn`）と「メロディ［スライダー］コード」（`#mix`、`aria-label` は「メロディ ←→ コード」）。
- 確かめたこと（Playwright、テンポ 150）：くり返しオンで「ここから」（枠20）は、終わると枠20の拍（44）からまた始まり、停止で止まる。「▶ 原曲」の聴き比べは 4〜20拍（4小節）をくり返す。再生中にテンポを変えても `play.start` は 44 のまま。mix 0／50／100 で（メロディ, コード）＝（1,0）／（1,1）／（0,1）。保存して読み込み直すと戻る。幅 480／1280px のツールバーを撮って目で確かめた。音そのものは耳で聞いていない。
- 気づいた点：くり返しは `playRange` 全体にかかるので、候補を選んだときの短い試聴（`previewSel`、逆算の試聴）も、くり返しオンなら止めるまでくり返す（「未決」に書いた）。

## G. 短調の階名をラから読む切り替え

**ねらい**　伴奏付けでコードを置く前、音符の下に階名が出る。短調でも主音をドとしているが、日本ではラから読む教え方も多い。

**仕様**
- 階名を返す所を1つの関数にまとめる：`solf(midi, K)`（`js/theory.js`）。`K` は `keyAt(...)` の返す調。
  - `K.minor` かつ設定 `state.laMinor` がオンのとき、主音をラとして読む。主音からの半音数 → 階名：
    `0 ラ, 1 シ♭, 2 シ, 3 ド, 4 ド♯, 5 レ, 6 レ♯, 7 ミ, 8 ファ, 9 ファ♯, 10 ソ, 11 ソ♯`
  - それ以外は今までどおり（`SOLF`、主音がド）。
- `SOLF[...]` を直接引いている所をすべて `solf` に替える：`roleOf` の未設定のときのラベル、`solfOf`（`js/guide.js`）、ガイドのステップ1の「最後の音が『ド・ミ♭・ソ』なら…」（`sf`）とフレーズ末の音（`sol`）。`roleOf(chord, midi, tonicPc)` の第3引数は `K` を受け取る形に変え、呼び出し側（`rolesSpan`、`vfSystem`）を合わせる。
- 切り替えは、楽譜の上の集計の行（`#summary`）の伴奏付けモードの側に、チェックボックス `短調はラから読む`（id `laOn`）。**曲（またはいま選んでいる枠の区間）が短調のときだけ**出す。`rehamo:la` に保存。
- I・IV・V の呼び名（Im・IVm・V）は変えない。変わるのは階名だけ。

**受け入れ条件**
1. 「世の人忘るな」の伴奏付けで、オンにすると音符の下が「ラ・ミ・ミ・レ…」になり、ステップ1の説明が「ラ・ド・ミなら Im、ミ・ソ♯・シなら V」になる。オフで「ド・ソ・ソ・ファ…」「ド・ミ♭・ソ」「ソ・シ・レ」に戻る。
2. 長調の曲では、チェックボックスが出ず、表示も変わらない。
3. `node --test` に、`solf` のテスト（長調、短調のド読み、短調のラ読み、導音がソ♯になること）を足す。

**実装メモ**
- `js/theory.js`：`SOLF_LA`（計画の表のまま）と `solf(midi, K)` を追加。`roleOf(chord, midi, K)` は第3引数を調に変え、`rolesSpan` と `vfSystem`（`vfEngrave`）の呼び出しを合わせた。
- `js/guide.js`：`solfOf` を消して `solf` に統一（ステップ1の `sf` と `sol`、ステップ3の骨格の音）。`SOLF[...]` を直接引く所は `solf` の中だけになった。
- `js/score.js`：集計の行（伴奏付け側）に `#laOn`。`isMinor() || keyOfCell(state.sel).minor` のときだけ出す。階名は楽譜のキャッシュ（A）に焼き込まれるので、キャッシュのキーに `state.laMinor` を足した。`rehamo:la` に保存し、`state.laMinor`（`js/state.js`）として読む。
- 確かめたこと：`node --test` に `solf` のテストを1つ足した（長調、短調のド読み、短調のラ読み、導音 B → ソ♯、D マイナーでも主音がラ）。「世の人忘るな」の伴奏付けで、オンにすると音符の下が「ラ・ミ・ミ・レ・ド・シ・ラ・ソ…」、ステップ1が「ラ・ド・ミなら Im、ミ・ソ♯・シなら V」、フレーズの最後の音も「ラ」「ミ」になる。オフで「ド・ソ・ソ・ファ…」「ド・ミ♭・ソ」「ソ・シ・レ」に戻る。きらきら星ではチェックボックスが出ず、オンのままでも表示は変わらない。スクリーンショット（1280／480px）を目で確かめた。

## H. フレーズの区切りを曲ごとに指定

**ねらい**　ガイドはフレーズを4小節ずつと決めている。収録曲はそれで合っているが、自分で入力した曲ではずれることがある。

**仕様**
- 曲データに、任意の項目 `phrases:[4,4,4,3]`（フレーズごとの小節数）を足す。`phrases()`（`js/guide.js`）は、これがあればその区切りを使い、なければ今までどおり4小節ずつ。
- `buildSong` で検査する：すべて正の整数で、合計が小節数に等しいこと。合わなければ無視して4小節ずつにする（例外は出さない）。
- 曲の入力画面（`openEditor`／`saveEditor`）に、任意の欄「フレーズの区切り（小節数。空なら4小節ずつ）」を足す。例：`4 4 4 4`。合計が小節数と合わないときは、保存せずにエラー文を出す（既存のエラー表示の仕組みを使う）：「フレーズの小節数の合計（○）が、曲の小節数（○）と合いません。」
- 収録曲には `phrases` を足さない（4小節ずつで合っている）。ガイドの文の「フレーズ（4小節ずつ）」は、`phrases` がある曲では「フレーズ」とだけ書く。

**受け入れ条件**
1. 6小節の曲を `2 4` で保存すると、伴奏付けのガイドのステップ1に、2小節と4小節のフレーズが出る。リハモのガイドのステップ1の下線（フレーズの終わり）もそれに合う。
2. 合計が合わない入力は保存されず、エラー文が出る。
3. 既存の保存済みの自作曲（`phrases` なし）が、今までどおり開く。

**実装メモ**
- `js/music.js`：`buildSong` が `phrases` を検査し、正の整数だけで合計が小節数に等しいときだけ `song.phrases` に入れる（それ以外は `null`。例外は出さない）。
- `js/guide.js`：`phrases()` は `song.phrases` があればその区切り、なければ4小節ずつ（最後は余りの小節数）。`phraseEnds()` などはそのまま `phrases()` を使う。ステップ1の文は、`song.phrases` がある曲では「フレーズ」とだけ書く。
- `js/app.js`／`index.html`：曲の入力に「フレーズの区切り（小節数。空なら4小節ずつ）」（`#fPhrases`、placeholder「例: 4 4 4 4」）。合計が合わないときは計画の文面でエラー。数字でない・0 を含むときは「フレーズの区切りは、小節数を空白で区切って書いてください（例：4 4 4 4）。」を出す（この文面は計画にないので足した）。入力の文字は `raw.phrases` に残し、編集で開いたときに戻す。「例を入れる」では空にする。
- 確かめたこと：`node --test` に `buildSong` の検査のテストを足した。Playwright で、6小節の曲を `2 3` で保存しようとするとエラー文が出て保存されない。`2 4` で保存すると、伴奏付けのステップ1が「フレーズ 1（1〜2小節）」「フレーズ 2（3〜6小節）」になり、リハモのステップ1の下線は 2小節目と6小節目の枠に付く。`phrases` のない古い自作曲は、今までどおり 1〜4／5〜6 小節で開く。曲の入力画面を幅 1280／480px で撮って目で確かめた。

## 確認の結果（2026-11-15、確認担当）

`node --test`（12件）と `python3 tools/smoke.py`（1410 回、エラー 0）は通った。差分を読み、幅 1280px／480px で動かして確かめた。
A・B・D・G・H は受け入れ条件どおり。A の速度は、確認した環境では 91 ms → 34 ms（実装担当の環境では 25 → 7 ms）。目標の 20 ms には届かない環境があるが、残りは VexFlow 以外の部分（DOM の作り直し）なので、A としては確認済みにする。

直す点（1つ＝1コミット。R1 と R2 は不具合なので先に）：

### R1.（F）くり返し中に枠を結合すると、再生がエラーで止まる
- 再現：きらきら星で「くり返す」をオン →「ここから」で再生 → 再生中に前のほうの枠を「次と結合」。くり返しの継ぎ目で `Cannot read properties of undefined (reading 's')`。
- 原因：`playRange` は開始時の枠の番号（`from`、`to`）を持ち続けるが、結合や分割で `state.chords` の長さが変わる。
- 直し方：くり返しの次の周回と `replayLater()` では、番号でなく**拍**から範囲を作り直す。`play` に範囲の開始拍と終了拍（`b0` の元の値＝`start`、`b1`）を持たせ、呼び直すときに「その拍の範囲にかかる枠」を今の配列から探す（`playCompare` の `findIndex` と同じやり方）。原曲の再生（`chords` が `origUnits()` のとき）はそのままでよい。
- 受け入れ：上の再現でエラーが出ず、くり返しが続く。分割したあとも、最後の枠まで鳴る。`tools/smoke.py` に、くり返し中の結合と分割を1回ずつ足す。

**実装メモ（R1）**
- `js/audio.js`：`play` に範囲の終了拍 `end`（`b1`）を足した（開始拍は F の `start`）。新しい `replayBeats(p, startBeat)` が、`start`〜`end` にかかる枠を今の `state.chords` から `findIndex` で探し直して `playRange` を呼ぶ（mode `"orig"` のときは `p.chords`＝原曲の枠のまま）。くり返しの次の周回と、`replayLater()`（`js/app.js`、テンポと mix の変更）の両方がこれを使う。
- `tools/smoke.py`：きらきら星（テンポ 150）で、くり返しオンで最後の3枠から「ここから」→ 再生中に枠0を結合 → 1周後に枠0を分割 → さらに1周、の検査を足した。再生が続き、3周以上し、最後の周回の `to` が枠の数と等しい（最後の枠まで鳴る）ことを見る。直す前のコードではこの検査が落ちる（分割後の周回が最後の枠を落とす）ことも確かめた。

### R2.（E）根音が同じなら「響きの厚さが違うだけ」と言ってしまう
- 再現：きらきら星の伴奏付けで、原曲 C の枠に C7 または Cm を置く →「原曲（C）と根音が同じで、響きの厚さが違うだけです。」と出る。C7 は F へ向かうセカンダリードミナント、Cm は借用で、働きが違う。
- これは計画の書き方が粗かった。場合分けの 3 を次に替える：
  「根音が同じ、かつ `A.kind==="dia"` かつ `O.kind==="dia"` かつ `A.fn===O.fn`」のときだけ 3 の文。
  それ以外で根音が同じときは、次の文（新しい場合 3b）：「原曲（○○）と根音は同じですが、働きが違います（△△）。」△△ は `A.note` があればそれ（例：「IV へ向かうセカンダリードミナント」「同主短調からの借用」）、なければ「調の外のコード」。
- 受け入れ：C → Cmaj7／C6 は 3 の文。C → C7 は 3b（セカンダリードミナント）、C → Cm は 3b（借用）。テストは不要（表示の文なので、Playwright で確かめる）。

### R3.（F・未決への答え）試聴はくり返さない
- 候補を選んだときの短い試聴と、逆算タブの試聴（mode `"slot"`）は、「くり返す」がオンでも1回で止める。くり返すのは、全体・ここから・前小節から・聴き比べ・原曲だけ。

### R4.（E・未決への答え）答え合わせの文は、狭い画面でも出す
- `answerNote` の文を `.vmsg` の中でなく、別の要素（`<span class="ansnote">`）にして、判定の行に置く。幅 720px 以下でも隠さない。文字の大きさと色は `.vmsg` と同じ。
- 受け入れ：幅 480px で、伴奏付け・「原曲のコードを見る」オンのとき、答え合わせの文が見える。

### R5.（C）「T・S・D」が文の中でボタンにならない所がある
- `RDESC.read` と、伴奏付けのステップ4の説明は、「T（安定）・S…」という書き方なので `glossed` が拾えない。文のほうを直す（文面はこのまま使う）：
  - `RDESC.read`：「まず原曲の骨組みを知ります。コードの機能（T＝安定、S＝広がり、D＝緊張）の流れと、フレーズの終わり（着地点の候補）を確かめましょう。原曲を一度聴いてから次へ進みます。」
  - 伴奏付けのステップ4：「コードの機能が、T（トニック）→ S（サブドミナント）→ D（ドミナント）→ T の流れになっているかを見ます。押すとその枠を選びます。」
- `GLOSS` に `["機能","fn"]` を足す。ただし「同じ機能で置き換える」のような見出し（`TECH[*].name`、ステップ名）は `glossed` を通していないので、そのままでよい。
- 受け入れ：リハモのステップ1と伴奏付けのステップ4で、「機能」を押すと説明が出る。

気づいた点（今回は直さなくてよい。次の計画の候補）：
- 楽譜のキャッシュが VexFlow の音符オブジェクト（`info` の `heads[].sn`）ごと抱えている。`x`・`label`・`kind`・`strong` などの値だけにすれば、メモリが軽くなる。
- 選択を変えただけのときは、楽譜の DOM を作り直さず、選択の印（クラス）だけ付け替えると、さらに速くなる。
- 幅 720px 以下では、選択中の枠のバーの「機能」「度数」も隠れている（以前からの挙動）。スマートフォンで度数を見たい場合は、ここも出す必要がある。
