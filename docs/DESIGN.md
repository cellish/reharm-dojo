## 2. 設計の決定（理由つき）

### 楽譜の表示と速さ
- **段ごとの組版を値だけでキャッシュする**（`vfCache`、上限64段、古い順に捨てる。第1期 A・第2期 J）。
  - 理由：枠を選ぶたびに全段を VexFlow で組み直すと、Tea for Two で1回約90ms かかり、矢印キーでの移動が重かった。
  - VexFlow のオブジェクトやクロージャを持つと、64段ぶんのメモリが残る。だから中身は値と SVG の文字列だけにし、時刻→x座標は外の `vfMap` で作り直す。
- **キャッシュのキーは、その段の見た目を決めるものすべて**：曲、調、段の位置と大きさ、枠の中身、音符の色（CSS 変数）、`state.laMinor`。
  - 選択・着地点の印・再生位置はキーに入れず、`svg()` が毎回 `state` から読む。
  - 理由：色や階名は音符に焼き込まれる。一方、選択は毎回変わるので、キーに入れるとキャッシュが効かない。
- **選択だけが変わるときは、楽譜を作り直さず印を付け替える**（`selectCell`。第2期 I）。
  - ただし、楽譜がまだ出ていないとき、印を付ける枠が見つからないとき、伴奏付けで長調と短調の区間をまたぐときは、`render()` で全体を描き直す。
  - 理由：キャッシュのあとも、8段ぶんの SVG を読み直す時間が残っていた。印を付け替えるだけなら、再生位置の印も消えない。
  - 迷うときは `render()` のままにする（選択以外の変化を取りこぼさないため）。
- **確かめ方**：キャッシュあり・なしと、`selectCell` 後・`render()` 後の両方で `#sheet` が一致することを `tools/smoke.py` で見る（VexFlow が振る `vf-auto…` の id は除く）。
  - 理由：見た目の食い違いを、目で見なくても見つけられる。

### 再生
- **くり返しの次の周回は、枠の番号でなく拍の範囲から枠を探し直す**（`replayBeats`。R1）。
  - 理由：再生中に枠を結合・分割すると番号がずれ、エラーで止まった。
- **試聴（mode `"slot"`）はくり返さない**（R3）。
  - くり返すのは、全体・ここから・前小節から・聴き比べ・原曲・案。
- **メロディとコードの音量の配分は2乗で絞る**（`melGain`／`chordGain`。F）。50 で以前と同じ音量。
  - 理由：直線で絞ると、端に近づくまで変化が聞き取りにくい。

### 判定と答え合わせ
- **伴奏付けの答え合わせは、原曲と同じかどうかでなく、その場所の調での機能で比べる**（`answerNote`。E）。
  - 理由：原曲と違っても成り立つ答えは多い。
  - 根音が同じでも、ダイアトニックで同じ機能のときだけ「厚さが違うだけ」と言う。C → C7 や C → Cm は働きが違うので、そう言わない（R2）。
- **答え合わせの文は判定の文と分けて置き、狭い画面でも出す**（`.ansnote`。R4）。
  - 文が下の固定パネルに隠れるときだけ、ページを送る（`showAnsNote`、`revealAboveSheet`）。
- **狭い画面でも「機能」「度数」「転調中」は見せる**。「原曲」「次」は楽譜で見えるので隠す（K）。
  - 理由：機能と度数は学習の要。

### クリシェはフレーズの中だけ（2026-11-21、利用者と決めた）
- **同じコードが続く所（クリシェの線）は、1つのフレーズの中だけで作る**（`techniques` の run を `phraseStartsAt` で切る）。
  - 理由：前のフレーズの終わりの I（終止）と、次のフレーズの頭の I は、続いている1つのコードではない（きらきら星の4〜5小節目）。
- **フレーズの終わりで終わる線は、次のフレーズのコードへ向かわせない**（「→ 次のコードへ」の線を出さず、戻る線だけにする）。
  - 理由：終止の I が I7 などに変わると、フレーズの終わりが弱まる（ジングルベルの1〜4小節目）。
- このため、きらきら星にはクリシェのお題がない。入門のクリシェのステップは「この曲にはありません」と出して先へ進む。

### 偽終止の呼び方（2026-11-21、利用者の指摘）
- **V → VIm を「偽終止」と呼ぶのは、同じフレーズの中だけ**（`phraseStartsAt`）。
  - 理由：前のフレーズを V で終えたとき（半終止）、次のフレーズの頭の VIm は、終わると思わせた V の解決先ではない。きらきら星の9小節目がこれに当たる。
  - フレーズの区切りは、ガイドの `phrases()` と同じ（曲の `phrases`、なければ4小節ずつ）。

### 学習の補助
- **用語は、文の中の語をその場で押せる形にする**（`glossed`、`GLOSS`、`TERM_TEXT`。C・R5）。
  - 1回の呼び出しで、同じ語は最初の1回だけボタンにする。候補ボタンと楽譜の中には使わない。
  - 「機能」と「T・S・D」が並ぶ文では、先に出る「機能」をボタンにする（利用者と決めた。説明の見出し「機能（T・S・D）」と合い、規則が1つで済む）。
- **階名を返す所は `solf(midi, K)` の1か所だけ**（G）。
  - 短調でラから読むかどうかは設定で切り替える（`state.laMinor`）。I・IV・V の呼び名は変えない。
- **フレーズの区切りは、曲データの任意の項目 `phrases` で決める**（H）。
  - なければ4小節ずつ。合計が小節数と合わないときは、読み込みでは黙って無視し、曲の入力では保存させない。
- **「はじめに」の案内は、閉じたら次から出さない**（`rehamo:intro`。D）。保存が使えない環境では毎回出る。
  - 開き直す「使い方」ボタンは、利用者の判断でなくした（2026-11-21）。
- **元に戻す・やり直すのショートカットは、ボタンに乗せたときに出す**（Mac は ⌘Z・⌘Shift+Z、ほかは Ctrl）。ボタンが押せないときも出るよう、外側の要素に付ける。

### 候補の一覧（置き換え候補・コード候補。第3期）
- **候補は同じ大きさのタイルにする**。手法ごとのグループは開閉できる。
  - 初期値は全部開く（利用者と決めた）。
  - 一番上で手法ごとに絞り込める。「ぶつかる候補を隠す」もある。
  - 理由：候補が多い枠で、全体が見渡せなかった。
- **長い説明は、一覧の上の1行に出す**。マウスでは乗せたとき、タッチ画面では長押し（450ms）で出す。長押しではコードを置かない（利用者と決めた）。
- **手法ごとの色は今のまま残し**、グループの線と絞り込みのボタンに使う（利用者と決めた）。

### 案と、コードを変える間隔（第3期）
- **1曲に案A〜案Eまで、モードごとに持つ**（`rehamo:p:`／`rehamo:hp:`）。
  - 新しい案は今の案の写しから始め、元の案が比べる相手になる。
  - 理由：リハモは何通りも試して比べるもので、1つの版を上書きすると前の版に戻れない。
  - 案ができる前に保存したコードは、最初の案として読み込む。
- **コードを変える間隔は拍子ごとに用意する**。4拍子は 1小節／2拍／1拍、3拍子は 1小節／2拍＋1拍／1拍。
  - どちらにも「骨格の音に合わせる」を用意する：1つの三和音に骨格の音が収まらない小節だけを分ける。
  - 切り替えても、その位置で鳴っていたコードを残す。
- **「逆算」タブは「着地点から」と呼ぶ**。鎖の各コードに、着地点を I とみなした度数を添える。
  - 理由：「逆算」では何をする所か分からない。

### 著作権（第3期）
- **オープンソースにせず、All rights reserved にする**（著作権者 jun、2026年）。
  - 理由：今はウェブで無料公開だが、将来は有料のアプリにする可能性がある。ライセンスはあとから緩められても、締めることはできない。
- 収める旋律は、日本と米国の両方で保護期間が終わったものだけ（`CLAUDE.md` の「曲データの決まり」）。

## 5. 入門コース（第5期）

### ねらい
今のガイドは、どの枠でも選べて、候補もすべて出す。どこをどう変えればよいか分からない人には広すぎる。
入門コースでは、ステップの並びはそのままに、各ステップで**アプリが枠を選び、候補を2〜3個に絞って**出す（お題）。

### 決めたこと（利用者と決めた。2026-11-21）
- **使える曲と、置き場所**
  - 伴奏付けとリハモの両方に作る。
  - 入門の4曲（きらきら星・歓喜の歌・ジングルベル・聖者の行進）だけで使える。
  - ガイドの一番上に「入門／ふつう」の切り替えを置く。4曲以外では「入門」を押せなくし、「入門コースは入門の4曲で使えます」と添える。
- **お題は、曲ごとに手で決めてデータに書く**（A の形）。
  - 理由：教える順とひとことを選べる。規則で選ぶ形（B）は、入門を作ってみてから考え直す。
- **お題の数**：使える所が多いステップでは2〜3か所、少ないステップでは1か所。
- **お題の形**：枠1つ（クリシェは続いている枠のまとまり）、候補2〜3個、ひとこと1文。
  - 候補のうち1つに「おすすめ」の印（★）を付ける。
  - 合わない例（判定が ✕）を1つ混ぜる。ただし**そのステップの候補の一覧にあるもの**から選ぶ（リハモは `techniques(i)` のその手法、伴奏付けはそのステップのボタン）。候補の一覧に ✕ がなければ、合わない例は出さない。
  - 一覧にないコードを、お題のために作らない。
- **リハモの入門は7ステップ**：原曲を読む → 音を足す → 同じ機能 → ベースを動かす → クリシェ → 向かう → 見直す。
  - 「半音で近づく」「借りてくる」は、入門を作ってから足すかを考える。
- **伴奏付けの入門は6ステップ**で、今のガイドと同じ並び。
- **お題を選んだあとの再生は1回**（2026-11-21、利用者と決めた）。置いたコードで前後4小節を鳴らし、楽譜に再生位置を出す。原曲と比べたいときは、枠のバーの「聴き比べ」を使う。
  - 理由：はじめは「原曲 → いまのコード」の2回にしたが、1回目（原曲）は再生位置が出ず、2回鳴る理由も分かりにくかった。
  - 入門で鳴らしている間は、パネルに「■ 再生を止める」を出す。
- **お題の文は、答えを言わない**（2026-11-21、利用者と決めた）。例：「I を、同じ機能（T）の VIm7 か IIIm7 に置き換えます。メロディと合うほうを選びます。」
- **お題の文の音名とコード名は、選んだ調で出す**。データには C の枠で `{n:E}`（音）・`{c:G7}`（コード）と書き、`sayText` が `droot`・`sym` で直す。
  - 理由：音名をそのまま書くと、移調したときや、原調が C でない曲（歓喜の歌）で食い違う。「ミ」のような階名も、固定ドと読み違えやすいので使わない。
- **進み方は「次へ」1つ**（2026-11-21、利用者と決めた）。「次へ」は同じステップの次のお題へ、最後のお題なら次のステップへ進む。ボタンに行き先（「お題 2」「ステップ 4」）を添える。
  - 理由：「次のお題へ」と「次へ」が並ぶと違いが分かりにくく、お題 2・3 に気づかず次のステップへ進んでしまうため。「とばす」も「次へ」と同じになるので消した。
- **切り替えは「入門」を左、「ふつう」を右**に置く（利用者と決めた）。
- **入門の記録を消す**：パネルの下の「入門の記録を消す」で、その曲・そのモードの済んだお題と開いていたステップを消す（確かめてから）。楽譜のコードは変えない（Undo と案で戻せるため）。

### 仕様

#### L1. 切り替えと保存
- **切り替え**：ガイドの上に「入門／ふつう」を置く。
  - 保存キーは `rehamo:course`（曲によらず1つ）。`rehamo:intro` は「はじめに」の案内で使っているので、使わない。
  - 入門の4曲以外を開いたときは、「ふつう」として扱う（保存した値は変えない）。
- **入門の進み具合**：ステップは、今のガイドと別に持つ。
  - 保存キーは `rehamo:cstep:<曲id>`（伴奏付けは `rehamo:hcstep:<曲id>`）。
  - 済んだお題は `rehamo:task:<曲id>`（伴奏付けは `rehamo:htask:<曲id>`）に、お題の id の並びで持つ。
- **案と Undo**：入門で置いたコードも、今の案に入る。Undo もそのまま効く。
- **伴奏付けの枠**：入門の伴奏付けでは、はじめから原曲と同じ枠（中身は空）にしておく。
  - 理由：お題の位置を決めておけるように。
  - 今の案が空なら、そのまま原曲の枠にする（Undo で戻せる）。
  - 今の案に何かコードが入っているときは上書きせず、「新しい案で始める」ボタンを出す。黙って案を増やさないため。

#### L2. お題の画面
- **お題を出すとき**：お題の枠を自動で選び、楽譜の上で光らせる（着地点の印と同じくらい目立つもの）。
  - パネルには次を出す：「お題 1 / 2」、ひとこと、候補のタイル（★、○✕の判定つき）。
- **候補を選んだとき**：そのコードを置き、前後4小節を「原曲 → 今のコード」の順に聴き比べる（今の `playCompare`）。
  - 合わない例を選んだとき：鳴らしてから、置く前のコードに戻す。そのうえで、ぶつかる音の説明（お題データの `why`）を出す。
- **お題が済む条件**：★か ○ の候補を置くと済む。済んだお題には ✓ を付け、「次のお題へ」を出す。
  - お題の枠に、すでにお題の候補と同じコードが入っていても済んだことにする。
- **とばす**：「このお題はとばす」を置く。とばしたお題は済んでいない扱いで、あとから戻れる。
- **ステップの印**：ステップの中のお題が全部済むと、ステップの印に ✓ を付ける。
  - 次のステップへは、済んでいなくても進める。
- **お題の枠以外を選んだとき**：そのステップの、ふつうのガイドと同じ中身を出す。上に「お題に戻る」ボタンを出す。
- **前提のコード**：伴奏付けのステップ5・6のお題は、その枠に前提のコード（例：I）が入っているときに出す。
  - 入っていないときは、「この枠を I にすると、このお題ができます」と、そのコードを置くボタンを出す。
- **伴奏付けのステップ3**：「残りの枠に原曲のコードを入れる」ボタンを、お題の状態によらず出す。
  - 自分で埋めたい人のために、今の「次に決める枠へ」も残す。
- **流れを確かめる（伴奏付けのステップ4）**：お題を決めておかない。
  - `flowIssues()` の最初の1件を、その場でお題にする。その枠を選ぶと、I・IV・V・V7 の候補を出す。
  - 気になる点がなければ済んだことにする。

#### L3. お題のデータ
- 置き場所：`js/songs.js` の末尾の `COURSES`（曲の id ごとに `{reharm:[…], harm:[…]}`）。曲データと同じ C の枠で書く。
  - 曲のデータとは分けた。お題は入門の4曲にしかなく、曲の行を読みにくくしないため。
  - 歓喜の歌は原調 D なので、データでは C に移して書く。
- 形の例（きらきら星）：

```js
twinkle:{ reharm:[
  {id:"s1", step:"seventh", bar:3, beat:3, say:"E はコードの3度です。7度や6度を足しても、メロディはよく乗ります。",
   picks:[{c:"Cmaj7", best:true}, {c:"C6"}]},
  {id:"f1", step:"func", bar:9, beat:1, say:"同じ T の仲間でも、メロディの音を含むかどうかで合い方が変わります。",
   picks:[{c:"Am7", best:true}, {c:"Em7", bad:true, why:"メロディの C が Em7 の音とぶつかります。"}]},
  … ]}
```
- 候補 `c` は、そのステップの候補の一覧にある名前で書く。
  - 一覧から外れたら、テストで落ちるようにする。

### お題を選ぶときに使った目安（データを足すときのため）
- **枠を分ける**：同じ曲の中では、ステップごとに違う枠を選ぶ。前のステップで変えた枠を、次のステップで上書きしないため。
  - 伴奏付けは、ステップ3で置いたコードをステップ5・6で広げるので、ステップ3と5・6は同じ枠でもよい。5と6は分ける。
- **曲の終わり**：曲の最後の枠は変えない（原曲の終わり方を残す）。
- **メロディが根音の所**：メロディが根音の所には、maj7 のお題を置かない（クリシェの線の途中も同じ）。判定は ○ でも、メロディの根音と長7度が半音でぶつかるため。
  - そのため、ジングルベルと聖者の行進のクリシェは、maj7 を通らない線だけにした。
- **区切りと終わり方のお題**：次の所はお題にしない。
  - フレーズの最後の音が、I にも V にも含まれない所（聖者の行進の4小節目・12小節目）。
  - 原曲と違うほうのコードに、最後の音が含まれる所（歓喜の歌の12小節目は、原曲が V なのに、最後の音 F♯ は I に含まれる）。
- **伴奏付けの★**：骨格の音を含むコード（今のガイドの「含むのは」）。
  - ステップ3では、○ でも骨格の音を含まないコード（テンションになるだけのもの）は候補に出さない。
  - ステップ1は今のガイドと同じく、I と V の2つをいつも出す。

## 5b. 半音の ♯IVm7(♭5) と「終わり方を替える」（第5期の続き）

### 決めたこと（利用者と決めた。2026-11-22）
- 「半音で近づく」に ♯IVm7(♭5) を足す。
- 「終止形を替える」は、新しい手法（ガイドのステップ）にする。
- どちらも入門と見本に入れる。

### M1. 半音で近づく：♯IVm7(♭5)
- **出す所**：長調で、根音が IV のコード（F・Fmaj7・F6 など。C の曲）の枠。次の枠の根音が I か V のとき。
- **候補**
  - 枠ごと ♯IVm7(♭5) にする：「♯IVm7(♭5)（ベースが半音上がって、次の ○ へ）」
  - 枠を2つに分けて、後半だけ ♯IVm7(♭5) にする：「後半を ♯IVm7(♭5) に（IV → ♯IV → ○）」
- **理由**：IV → ♯IVm7(♭5) → I/5（または V）と、ベースが半音ずつ上がる。m7(♭5) の最もよく使われる形で、今の「半音で近づく」（♭II7・dim7）にない。
- 綴り：根音は IV と同じ文字に ♯ を付ける（`upIv(root, 0, 1)`。F → F♯）。
- 受け入れ条件：きらきら星の10小節目（F、メロディ A）で ○ の候補に出る。聖者の行進の12小節目（メロディ F）では ✕ になる。短調の曲では出ない。

### M2. 新しい手法「終わり方を替える」（`cadence`）
- **名前**：「終わり方を替える」（短い名前は「終止」）。
- **置き場所：`TECH_ORDER` の最初**。ガイドでは「原曲を読む」のすぐあと（2番目）のステップになる（2026-11-22、利用者と決めた。はじめは最後に置いていた）。
  - 理由：フレーズの終わりは、そこを着地点としてコードを決める所。先に終わり方を決めれば、あとの「向かう」や「着地点から」は、決めた着地点へ向かうコードを提案する。
  - IVm6・♭VII7（借りてくる）と ♭II7（半音で近づく）は、それを説明するステップより先に出る。候補の名前と説明に「同主短調から借りる」「半音上から下りる」と一言添える。
- **出す所（終止の点）**：V（D の機能で根音が V）の次の枠が I で、その I がフレーズの最後の枠のとき。
- **V の枠に出す候補**（長調）
  - 変格終止：IV → I
  - IVm6 → I（同主短調から。柔らかく暗い終わり方）
  - バックドア：♭VII7 → I
  - バックドアの II–V：枠を2つに分けて IVm7 – ♭VII7
  - 裏コード：♭II7 → I
- **V の枠に出す候補**（短調）
  - 変格終止：IVm → Im
  - 裏コード：♭II7 → Im
- **I の枠に出す候補**（曲の最後の枠では出さない）
  - 偽終止：長調は VIm7、短調は ♭VImaj7。
- **ほかの手法との重なり**：終止の点では、同じコードを「同じ機能」「半音で近づく」「借りてくる」に二重には出さない（「終わり方を替える」を先に作る）。
- **理由**：リハモでは、フレーズの終わりの味を選び比べることが多い。重なる候補はあるが、「終わり方」としてまとめて比べられるようにする。
- ガイドの説明（`RDESC`）と、タイルの色（`.t-cadence`）を足す。
- 受け入れ条件
  - きらきら星の4小節目前半（G7 → C、フレーズの終わり）に、IV・IVm6・♭VII7・♭II7 が「終止」として出る。
  - 同じ枠の「借りてくる」と「半音で近づく」には、それらが出ない。
  - 8小節目後半の G7（半終止。次の C は新しいフレーズの頭）には出ない。
  - 曲の最後の I には偽終止を出さない。

### 決めたこと（2026-11-25、Opus）
- **特徴は型で決める**：ジャンルごとに「特徴の型」（下の表）を決め、どの型も、そのジャンルの2曲以上で出す。1曲だけだと、曲の個性と区別がつかないため。
- **説明文は2文**：1文目はジャンルの特徴（全曲で同じ文。`GENRE_TRAITS`）、2文目はこの曲ですること（`desc`）。どちらも60字ほど。`desc` に書いた和音は、完成例に必ずあること。
- 足す案は、アプリの判定で骨格の音に ✕ がないことを確かめてから入れる。旋律に合わない型は、その曲では使わない（例：王道進行は、きらきら星の 7–8小節、歓喜の歌の 15小節では ✕）。
